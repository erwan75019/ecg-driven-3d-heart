ABOUT THE DEMO

HOW TO USE

  • Select a Record to load an ECG sample.
  • Press Play to start playback and Pause to stop at the current time.
  • Open More options to change speed or view the report and user guide.
  • Press Restart to return to the beginning.
  • In More options, use Show filtered ECG to compare the signals.
  • Follow the current P, QRS or T phase during playback.

Website user guide

Quick start

Explore a recording

  1. Choose a record and heart model. Use the previous/next arrows to move through records, or Import ECG to load your own CSV or JSON file. The selectors load an ECG and one of the available animated heart models.
  2. Inspect the heart. Choose Orbit around heart to circle the stationary model, or Free camera to move and look independently. In Free camera, drag to look around, right-drag to move sideways, or use two fingers to pan/pinch. Focus the viewer and use W/S to move forward/back, A/D sideways and Q/E down/up. Reset view returns to the initial framing. The model size slider ranges from 0.5× to 4×.
  3. Play the cycle. Use Restart, Play and Pause. Open More options to change speed, switch the signal, open the report or read this guide.
  4. Position the timeline. Click or drag along the ECG trace to move the cursor to that moment. This does not start playback; use Play to resume, with the heart synchronized to the selected time.
  5. Compare signals. Use Show filtered ECG to switch between the recorded and filtered traces.
  6. Read the report. View report opens the signal comparison, filter settings, and P-onset-to-QRS-peak measurements. Use Print / Save as PDF to export it.

The shaded P, QRS and T regions come from the dataset annotations. The selected animated model follows the ECG timeline, while filtered QRS amplitude above the local baseline noise modulates the visual strength of each beat. Without valid QRS activity the model remains in its reference pose. This educational effect is not a direct measurement of mechanical cardiac contractility and is not a medical diagnostic tool.

Data workflow

Add a new ECG recording

Universal ECG import: Import a CSV or JSON file directly from your device.

Use Import ECG for a local file: choose the sampling rate, signal column, separator and header setting for CSV. JSON files can include existing annotations. Missing QRS are estimated; P and T are not detected. Local imports disappear when the page is reloaded. The steps below describe adding records permanently to the bundled dataset.

  1. Prepare the signal. Use a single, evenly sampled ECG channel and keep its sampling rate in Hz. The current 0.5–40 Hz filter needs a sampling rate above 80 Hz and more than 27 samples.
  2. Annotate the waves. Provide P, QRS and T intervals as start/end times in seconds, measured from the beginning of the recording.
  3. Match the web format. Save one JSON file per recording with label, fs, ecg (the numeric samples), and intervals (arrays of time pairs for P, QRS and T). The format follows the existing files in web/data/ludb/records/.
  4. Register each record. Add the JSON file as record-ID.json and add its id and label to web/data/ludb/index.json. IDs must be unique and match the filenames.
  5. Check the result. Reload the site using a local web server, select the record, inspect its annotations and filtered signal, and open the report to verify the measurements.
Click for more details — JSON example

This short example illustrates the structure. An imported signal needs at least 28 numeric samples.

{
  "label": "Example ECG",
  "fs": 500,
  "ecg": [0.02, 0.08, 0.16],
  "intervals": {
    "P": [[0.10, 0.18]],
    "QRS": [[0.20, 0.28]],
    "T": [[0.35, 0.50]]
  }
}

See the reference ECG record for a complete example in the format used by the application.

signal-processing/export_ludb_for_web.py exports the project's LUDB source data; it is not a general importer for other dataset formats. Convert other datasets to the same JSON structure first, and check their usage terms and privacy requirements. The Import ECG button reads CSV and JSON files locally; it does not upload your data. Missing QRS annotations can be estimated; P and T annotations are not generated.

Libraries, data and signal processing

  • Three.js 0.160 is the browser's 3D rendering engine. GLTFLoader loads glTF/GLB models and OrbitControls provides interactive camera controls. Three.js is served from the unpkg CDN. Three.js official site.
  • The Python scripts use NumPy, SciPy and Matplotlib for numerical processing and signal visualization.
  • ECG recordings and annotations come from the Lobachevsky University Electrocardiography Database (LUDB), distributed by PhysioNet. Any reuse or publication must follow the dataset's terms of use and include the bibliographic citation provided on its PhysioNet page.
  • The project uses a 0.5–40 Hz, order-4 Butterworth band-pass filter. The Python script uses scipy.signal.butter and scipy.signal.sosfiltfilt; the website uses a JavaScript implementation of the same filter type. Filtering is not ECG wave detection.
