ABOUT THE DEMO

Visual ECG and cardiac cycle learning

This interactive application plays real ECG recordings and highlights the P wave, QRS complex and T wave to illustrate the electrical activity of the cardiac cycle.

02

HOW TO USE

  • Select a Record to load an ECG sample.
  • Choose a speed and press Play to start playback.
  • Use Pause to stop at the current time.
  • Press Restart to return to the beginning.
  • Use Show filtered ECG to compare the raw and filtered signals.
  • Follow the current P, QRS or T phase during playback.

Website user guide

Quick start

Explore a recording

  1. Choose a record and heart model. The selectors load an ECG and one of the available animated heart models.
  2. Play the cycle. Use Play, Pause, Restart, or choose a playback speed.
  3. Position the timeline. Click or drag along the ECG trace to move the cursor to that moment. This does not start playback; use Play to resume, with the heart synchronized to the selected time.
  4. Compare signals. Use Show filtered ECG to switch between the recorded and filtered traces.
  5. Read the report. View report opens the signal comparison, filter settings, and P-onset-to-QRS-peak measurements. Use Print / Save as PDF to export it.

The shaded P, QRS and T regions come from the dataset annotations. The selected animated model follows the ECG timeline. This is an educational visualization, not a medical diagnostic tool.

Data workflow

Add a new ECG recording

  1. Prepare the signal. Use a single, evenly sampled ECG channel and keep its sampling rate in Hz. The current 0.5–40 Hz filter needs a sampling rate above 80 Hz and more than 27 samples.
  2. Annotate the waves. Provide P, QRS and T intervals as start/end times in seconds, measured from the beginning of the recording.
  3. Match the web format. Save one JSON file per recording with label, fs, ecg (the numeric samples), and intervals (arrays of time pairs for P, QRS and T). The format follows the existing files in web/data/ludb/records/.
  4. Register each record. Add the JSON file as record-ID.json and add its id and label to web/data/ludb/index.json. IDs must be unique and match the filenames.
  5. Check the result. Reload the site using a local web server, select the record, inspect its annotations and filtered signal, and open the report to verify the measurements.

signal-processing/export_ludb_for_web.py exports the project's LUDB source data; it is not a general importer for other dataset formats. Convert other datasets to the same JSON structure first, and check their usage terms and privacy requirements. The site currently reads local JSON files; it does not upload data.
